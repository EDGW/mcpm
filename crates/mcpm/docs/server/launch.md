# Launch and attach

`mcpm launch` starts a Minecraft server. `mcpm attach` connects to a running server. Both use the same log, status, and command interface.

## Quick start

```sh
mcpm init ./server --start-script run.sh
mcpm launch --server ./server
```

To run the server in the background:

```sh
mcpm launch --server ./server --detach
```

The command prints a run ID and returns. Reconnect with `mcpm attach --server ./server`.

## `mcpm launch`

```text
mcpm launch [OPTIONS]
```

Reads `launch.toml` and `conf.toml`, builds the Java command, and starts the server. Before launch, it checks Java, prepares authentication, and validates required files. On success, it enters the interactive interface by default.

If a server instance is already running, `launch` reports an error. Attach and stop the old instance first.

### Options

#### Target

| Option | Description |
| --- | --- |
| `--server <PATH>` | Registered server directory. Defaults to the current directory. |

#### Launch overrides

| Option | Description |
| --- | --- |
| `-j`, `--java <EXECUTABLE>` | Java executable. |
| `-m`, `--memory <[INITIAL:]MAXIMUM>` | Maximum heap; optionally also the initial heap. |
| `-G`, `--gc <COLLECTOR>` | Garbage collector. |
| `-p`, `--port <PORT>` | Server port. |
| `--world <DIRECTORY>` | World directory. |
| `-E`, `--extra <ARGUMENT>` | Append one JVM argument. |
| `-O`, `--override <KEY=VALUE>` | Override any configuration field. |

See [Temporary overrides](#temporary-overrides) for syntax.

#### Authentication

| Option | Description |
| --- | --- |
| `-A`, `--auth <API_URL>` | authlib-injector API URL for this launch. |
| `--auth-jar-policy <POLICY>` | Managed authentication JAR policy: `auto`, `local`, or `refresh`. |

See [Authentication](#authentication) for configuration details.

#### Runtime and interface

| Option | Description |
| --- | --- |
| `-c`, `--communication <MODE>` | Command channel: `auto` (default), `rcon`, or `stdin`. |
| `-D`, `--detach` | Print a run ID and return without entering the interactive interface. |
| `--no-ui` | Use Console/Raw output instead of the TUI input area. |
| `--input-height <LINES>` | Initial TUI input height, at least 3 lines. Defaults to 4. |

Common options `--ssh`, `--ssh-mcpmd`, `--raw`, `--log-level`, and `--remote-logs` are described in the [README](../README.md).

### Examples

```sh
mcpm launch --server ./server
mcpm launch --server ./server --detach
mcpm launch --server ./server --communication rcon
mcpm --ssh 'ssh user@host' launch --server /srv/minecraft
```

### Temporary overrides

Overrides apply to this launch only and are not written back to `conf.toml`.

The most common settings have shortcut options:

```sh
mcpm launch --server ./server -j /opt/jdk/bin/java -m 1G:4G -p 25566
mcpm launch --server ./server -G g1 --world another-world
mcpm launch --server ./server -E '-Dfile.encoding=UTF-8'
```

Use `-O` to override any configuration field:

| Form | Behavior |
| --- | --- |
| `-Okey=value` | Set a scalar; append one item or array to a list. |
| `-Okey+=value` | Append a list item or array. |
| `-Okey:=value` | Clear the list, then set the new value; omit the value to clear. |

Examples:

```sh
mcpm launch --server ./server -Ojvm.threadStack=2M
mcpm launch --server ./server '-Ojvm.extraArguments:=["-Dfirst=1"]'
mcpm launch --server ./server '-Ojvm.extraArguments=-Dsecond=2'
```

Configuration keys use the full path and casing from `conf.toml`. Values are parsed as TOML or as unquoted strings. Quote the whole argument when it contains spaces.

A field may be set only once. Using a shortcut and `-O` for the same field is an error.

### Configuration files

| File | Contents |
| --- | --- |
| `launch.toml` | JVM arguments, entry point, fixed application arguments, working directory, and environment variables. |
| `conf.toml` | Java, memory, GC, authentication, Minecraft launch arguments, and user-supplied arguments. |
| `.mcpm/server.json` | Minecraft and Loader identity registration. |

`launch` reads `launch.toml` and `conf.toml` from the `--server` directory. If either file is missing, `launch` reports an error.

`launch.toml` is normally generated by `mcpm init` from the start script. `conf.toml` holds persistent user settings and can be edited directly.

```toml
# launch.toml: JAR server
[entry]
type = "jar"
path = "server.jar"
```

```toml
# conf.toml: Java and memory settings
[java]
executable = "java"

[jvm.heap]
initial = "1G"
maximum = "4G"

[server]
nogui = true
```

After changing the start script, run `mcpm init --force` to regenerate the launch configuration. `--force` preserves the existing `conf.toml` by default. Add `--foverride-conf` to rebuild `conf.toml` as well.

### Paths and arguments

- `process.workingDirectory` sets the Java working directory. It defaults to the server root.
- A bare `java.executable` name is resolved through `PATH`. A relative path is resolved from the server root.
- Each string in an argument array is one argv entry and is passed without shell expansion.
- Entry points support `class`, `jar`, and `module`.
- `server.port` and `server.world` only produce launch arguments. They do not modify `server.properties`; the server decides whether to accept them.
- An explicit `auto` value for memory or GC returns an error. Omitting these fields lets the JVM decide.

### Startup progress

During preparation, stderr shows the current step: reading configuration, checking Java, preparing authentication, and starting Java. When the terminal supports dynamic drawing, all steps update in one progress area; downloads show their source, progress, and speed. `--raw` or redirected stderr switches to line-by-line output.

After Java starts, the progress area is cleared and the command enters the interactive interface or returns a run ID. Preparation completion only means the Java process exists; whether Minecraft is ready is determined by the game itself.

### Authentication

Add an API URL to `conf.toml` to enable authlib-injector:

```toml
[authlib-injector]
apiUrl = "https://example.com/api/yggdrasil/"
```

| Field | Behavior |
| --- | --- |
| `jar` omitted or empty | mcpm manages the authentication JAR and selects a local copy or downloads one. |
| `jar = "libraries/custom-agent.jar"` | Use the specified file, relative to the server root. Only checks that the file exists and is readable. |

`-A` overrides the API URL for this launch only; other authentication settings remain unchanged.

`--auth-jar-policy` controls the managed JAR:

| Policy | Behavior |
| --- | --- |
| `auto` (default) | Use the local file when valid; download the latest release when it is missing, damaged, or its digest does not match. |
| `local` | Use only the local file; report an error when repair is required. |
| `refresh` | Download the latest release again. |

- `--auth-jar-policy` applies only to the managed JAR. It is an error to specify a policy when using a manual JAR or when authentication is disabled.
- A download or verification failure blocks launch and preserves existing files.
- Cancelling launch stops the download and removes temporary files.

## `mcpm attach`

```text
mcpm attach [OPTIONS]
```

Connects to a running server. After connecting, you can view logs and status and send commands.

By default, it replays the most recent screen of logs and then continues with live output. `--history-lines 0` disables replay and shows only live output. If the instance has exited, `attach` reports an error; use `launch` to create a new instance.

### Options

| Option | Description |
| --- | --- |
| `--server <PATH>` | Registered server directory. Defaults to the current directory. |
| `--history-lines <LINES>` | Number of history lines to replay. Defaults to the terminal height, or 24 when unavailable. |
| `--input-height <LINES>` | Initial TUI input height, at least 3 lines. Defaults to 4. |
| `--no-ui` | Use Console/Raw output instead of the TUI input area. |

### Examples

```sh
mcpm attach --server ./server
mcpm attach --server ./server --history-lines 100 --input-height 5
mcpm --ssh 'ssh user@host' attach --server /srv/minecraft
```

## Output modes

| Mode | Selection | Output |
| --- | --- | --- |
| TUI | Default in a terminal | Bottom input area; logs appear in the terminal history above it. |
| Console | `--no-ui` | Ordinary line-based output with line-based command input. |
| Raw | `--raw`, or stdout is redirected | No interaction, formatting, or colors; raw output. |

TUI requires both stdout and stderr to be terminals. Java stdout is treated as the game log; stderr and RCON responses are labeled separately. Diagnostics, progress, and hints use stderr and never occupy stdout.

## Command input and hints

When the input is nonempty, the interface shows command hints:

- Tab fills the selected candidate. Enter sends the current input.
- Up to five candidates are shown. Full matches come first, and long syntax wraps.
- With empty input, Up/Down browses recently submitted commands. Editing returns to hint mode.
- Recognized `/gamerule` syntax enables rule and value hints. Unknown rules are marked in red, and Enter still sends the original input.
- After connecting over RCON, the server help is loaded automatically. If loading fails, the hint area shows `Failed to fetch help`.
- Console and Raw accept line input and do not draw the hint panel.

## Built-in commands

| Command | Behavior |
| --- | --- |
| `@detach`, Ctrl+D, stdin EOF | Disconnect the current interface; the server keeps running. |
| `@stop` | Send a normal stop. |
| `@kill` | Force-stop Java immediately. |
| `@speed` | Toggle the compact and full rate displays. |
| `@@detach`, `@@stop`, `@@kill`, `@@speed` | Send the corresponding command to the server as literal text. |

When disconnecting, mcpm waits for submitted command results to finish before closing the current client.

The first Ctrl+C sends a normal stop; pressing Ctrl+C again while stopping force-stops Java. Force-stop has no automatic timeout. Java's exit code is returned as the command result.

## Rate display

In the TUI, `@speed` toggles the rate line below the status bar.

- Compact mode shows the average send and receive rates over the last 100ms.
- Full mode shows 100ms and 1000ms peaks and averages.
- Console and Raw have no persistent rate line; `@speed` prints one snapshot.

## Multiple clients

Multiple clients can connect to the same server and send commands. mcpm executes normal commands in order.

- Results from other clients use a green border and the `Executed by another Listener` label.
- Console shows the same border; Raw keeps only the source label.
- A new connection receives only command results produced after it connects; earlier results are not replayed.
- If a client falls behind, the interface reports the number of missed results while the server keeps running.

## Logs

- Java stdout and stderr are labeled separately; both streams are received continuously.
- Only recent log output is retained; older content is reported as missing.
- A `History` divider appears before replayed lines.
- Timestamps are gray. Level blocks are colored by INFO, WARN, ERROR, DEBUG, and TRACE; bodies at WARN and below are gray.
- RCON responses use a bordered block titled `RCON: <command>`.
- Raw preserves Java stdout bytes. Log colors, the history divider, and RCON borders appear only in other modes.
- `NO_COLOR` disables colors.

## Status and RCON

The status bar shows the Java lifecycle, server communication state, and the active command channel.

| Channel | Behavior |
| --- | --- |
| `auto` (default) | Prefer RCON; fall back to stdin when connection or authentication fails. |
| `rcon` | Use the existing RCON configuration; fall back to stdin when connection or authentication fails. |
| `stdin` | Use Java stdin only. |

- RCON requires existing server configuration.
- RCON commands return complete responses synchronously. stdin only acknowledges that a command was sent; read the response from Java stdout.
- If the connection drops or times out after sending, the result is marked unknown and is not replayed.
- Successful authentication shows `Server RCON Connected`; this state does not mean Minecraft is ready.
- When RCON is disabled, its configuration is missing, or `stdin` is selected, the state shows `Server Unknown`.
- If the status connection is lost, `attach` reports an error and keeps the state unknown.
- A connection failure only means the server is temporarily unreachable; Java may still be running.
- Only one running instance is allowed per server. A conflicting instance identifier causes the new launch to be rejected.
