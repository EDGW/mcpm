# Stash 操作

Stash 是服务端 `mods/` 目录的一份已保存快照。每个快照有名称、UUID 和创建时间，并记住每个文件的
路径、大小和内容校验和。凭这些信息，可以拿工作区与快照比较、确认快照是否完好，或把快照恢复回来。

**HEAD** 是工作区最近一次保存或切换到的快照，`status` 以它为比较基准。HEAD 只表示工作区从哪里
出发，不表示工作区没有被修改。

## 操作

| Operation | 作用 |
| --- | --- |
| `server.stash.create` | 把当前 `mods/` 保存为新快照，并设为 HEAD |
| `server.stash.switch` | 用某个快照的内容替换 `mods/`，并设为 HEAD |
| `server.stash.status` | 显示 `mods/` 与 HEAD 的差异 |
| `server.stash.list` | 列出所有快照 |
| `server.stash.info` | 显示选中快照的详细信息 |
| `server.stash.rename` | 修改一个快照的名称 |
| `server.stash.delete` | 删除选中的快照 |
| `server.stash.verify` | 检查选中的快照是否仍然完好 |

## 指定快照

`switch` 和 `rename` 只作用于一个快照；`info`、`delete`、`verify` 作用于一组快照。每个快照用
精确名称或 UUID 指定，名称不会被当作 UUID 解读。

指定一组快照时：

- 按给定顺序处理。
- 同一快照被指定多次（例如先按名称、再按 UUID），只处理一次。
- 找不到的快照只让它自己的那一项失败，其余照常处理。

## 进度

`create`、`switch`、`status`、`verify` 在工作过程中持续报告进度，最后给出一个最终结果；
可以限制同时处理的文件数。调用方不再读取时，操作随后停止，已经写入的文件保留。

## 并发

`create`、`switch`、`rename`、`delete` 会修改快照，因此不能与同一服务端上的其他 stash 操作同时
进行；只读操作之间可以同时进行。遇到服务端正忙时立即失败，不排队等待。

## 失败

失败要么终止整个操作，要么只影响其中一项。

| Operation | 单项失败 |
| --- | --- |
| `list`、`info` | 读不出的快照、读不出的 HEAD 在原位置报告，其余仍照常返回 |
| `verify` | 读不出的 HEAD 报告一次；每个快照各有自己的结果 |
| `delete` | 每个快照各有自己的结果 |

单项失败保留完整的原始错误链，见 [mcpm-exec 错误模型](../../../mcpm-exec/src/docs-zh/error.md)。
其余失败都会使整个操作报错。连接中断不会撤销已经写入的文件和已经发生的 HEAD 变更。

## `create`

计算当前工作区的校验和，保存为新命名的快照，并设为 HEAD。与 HEAD 完全相同的工作区会被拒绝，
因为再存一份相同的快照没有任何新信息。

如果保存失败，清理写到一半的数据也失败，错误会同时报告两者，并指出残留的备份目录。

## `switch`

把快照恢复到 `mods/`，并设为 HEAD。

- 先完整校验快照，即使指定了 `force`、即使它已经是 HEAD 也一样，因此内容缺失或损坏的快照
  不会覆盖工作区。
- 替换是整体的：不在快照中的文件会被删除。
- 工作区与 HEAD 不同，或不存在 HEAD 时，只有指定 `force` 才会替换。`force` 只表示允许丢弃修改，
  不会跳过校验。
- 不会自动保存当前状态。想保留当前修改，先 `create` 一个快照。
- 结果会说明是否真的发生了替换。

## `status`

逐文件比较 `mods/` 与 HEAD。HEAD 里有、工作区没有的文件为缺失，工作区有、HEAD 里没有的为多出，
内容不同的为已修改，并同时给出两边的记录。没有 HEAD 时无从比较，结果会如实说明。`status` 只读取
工作区和已保存的校验和，不写入任何内容。

## `list`

返回每个快照的名称、UUID、创建时间和备份位置，不计算工作区校验和，也不打开任何备份。排序由
调用方决定。

## `info`

对选中的快照返回与 `list` 相同的信息。指定 `include_manifest` 时，还返回每个快照的校验和、文件
列表和大小。读取这些信息不等于校验文件。

## `rename`

修改快照名称；UUID、创建时间、内容和是否为 HEAD 都不变。改成原有名称时直接成功。与列表类
操作不同，失败会使整个操作失败。

## `delete`

删除选中的快照；`mods/` 和被其他快照共用的内容不受影响。

- HEAD 不能被删除。选中的快照里包含 HEAD，或 HEAD 读不出来时，不会删除任何快照，整个操作失败。
- 否则每个快照各有自己的结果，部分失败后可以重试。
- 备份已经不存在的快照仍然可以删除。

## `verify`

检查选中的快照是否仍然完好：备份格式正确，清单中的每个文件都存在且大小一致，完整校验和也吻合。
它只读取该服务端自己保存的内容，不使用 global cache，也不看当前的 `mods/`。快照逐个检查。
HEAD 只用于报告读不出的情况，不会妨碍选中快照的检查。
