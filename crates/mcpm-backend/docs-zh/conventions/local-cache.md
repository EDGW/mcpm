# 通用本地缓存

`local::cache` 保存不可变内容和独立编码的附加元数据，不依赖 Loader、Mod 识别、
来源服务、凭据或输出界面。Mod 与来源业务可以在其上实现类型化适配层。

## 目录和布局

```text
<cache>/
├── .mcpm/
│   ├── metadata.json          # {"version":3}
│   ├── index.sqlite3          # 可选的派生 imohash 索引
│   ├── index.sqlite3-wal
│   ├── index.sqlite3-shm
│   └── index.lock             # 索引恢复协调
└── <BLAKE3前两位>/
    ├── <完整BLAKE3>           # 不可变内容
    └── <完整BLAKE3>.<metaname>.json
```

- `Blake3Hash` 为 32 字节，展示、解析和序列化统一使用 64 位小写十六进制。
  相同 key 表示相同内容。
- `CacheDir::new(path)` 只打开已有合法目录，不执行初始化。
- `CacheDir::initialize(path)` 创建不存在或空的目录，也接受已合法初始化的目录。
  非空且无有效 manifest 的目录、版本不兼容的目录均拒绝。
  父目录中的 `.mcpm-cache-init.lock` 持久协调并发初始化；初始化可能需要父目录写权限，
  并等待其他初始化操作。
- 打开后保留规范绝对路径。受管理的分片、内容、元数据和索引路径不能使用符号链接。
  操作进行时不要删除协调文件。
- 版本 2 的 Mod 缓存使用另一份 manifest 和 `.dat` 内容名。本接口不会接管或迁移旧目录，
  数据迁移必须显式进行。

## 操作和结果

| 操作 | 行为 |
| --- | --- |
| `import` | 返回完整内容 key；已有相同内容经过验证后复用 |
| `import_with_outcome` | 另外返回本次是否发布内容以及实际传输方式 |
| `export_file` | 导出单个目标并返回实际方式；内容缺失为错误 |
| `export` | 导出到缓存外、父目录已存在且目标不存在的位置 |
| `export_with_outcomes` | 另外返回每个已完成目标的规范路径与实际方式 |
| `entry(key)` | 观察普通内容文件与排序后的普通元数据名称；内容不存在返回 `None` |
| `list()` | 返回排序后的普通内容 key，忽略孤立元数据和非规范名称 |
| `inspect(key)` | 只观察结构：内容类型/大小和各元数据类型，包括孤立元数据 |
| `scan()` | 枚举所有受管理 key，包括异常类型和孤立元数据；每行保留自己的观察错误 |
| `check(key)` | 完整 BLAKE3 校验；缺失为 `None`，通过为 `Some(())`，损坏或 I/O 失败为错误 |
| `open_content_with_mode(key, mode)` | 显式选择结构检查或完整校验，并固定内容句柄 |
| `open_content(key)` | 固定并完整校验只读内容，缺失返回 `None` |
| `find_file(path)` | 只读查询输入文件对应的缓存 key |
| `find_content(path)` | 同样查询，并保留固定内容句柄及匹配方式 |
| `rebuild_index()` | 显式从已验证内容重建可选索引，跳过无效对象 |
| `try_read_metadata<T>` | 完整验证内容后，通过对应 `Codec` 读取具名快照 |
| `write_metadata<T>` | 完整验证内容，编码后原子替换完整元数据快照 |
| `remove(key)` | 删除内容及所有受管理的元数据名，包括孤立快照；其他硬链接保留 |

- `CacheLinkPreference` 支持 `Copy`、`HardLink`、`PreferHardLink`。
  只有跨文件系统或不支持硬链接的能力错误才允许回退复制。
- 新导入和导出先暂存、校验，再不覆盖发布内容。导入结果区分本次发布和复用，
  不会为了关联另一个源文件而替换已有对象。
- 导入保护内容免于普通原地写入。硬链接共享保护，包括最初的源文件；导出的复制副本可写。
- 导出先预检全部目标，再逐个独立发布。后续目标失败时，先前已完成的导出仍保留。
  需要逐目标处理错误时，每次只传入一个目标。
- 删除不递归移除目录、不接管未知名称；失败可能留下部分对象，并发发布可以重新创建名称。
- 文件操作保留原始错误及 `anyhow` 上下文；完整哈希不符还可识别为 `ContentHashMismatch`。

## 内容句柄和元数据所有权

- `CacheContent` 提供 key、规范路径、大小、只读文件和 `verification()`。
  文件游标最初位于零；读取和克隆共享游标。使用路径进行业务操作前后调用 `validate()`，
  在保留最初文件观察的同时检查普通替换与内容变化。
- `CacheContent::try_read_metadata<T>()` 不再次完整哈希内容，适合在 `open_content`
  或 `find_content` 后复用句柄读取元数据。
- 元数据名是非空的普通字符串，例如 `loaders`、`loader.details`、`加载器信息`。
  保留中文、空格和点；拒绝路径分隔符、控制字符和 Windows 文件名禁用字符
  `:`、`*`、`?`、`"`、`<`、`>`、`|`。缓存生成文件路径时追加 `.json`，
  返回名称时只移除这个存储后缀；`loader.details` 对应 `<blake3>.loader.details.json`。
- 所有元数据文件访问均通过 `CacheDir` 或 `CacheContent`；适配层与使用方调用这些接口，
  不直接打开或写入元数据路径。
- 每类快照只有对应 `Codec` 解释。缓存负责字节和原子发布，适配层负责格式版本、
  业务可用性、刷新策略，以及元数据与实际内容之间的语义关联。
- 内容或元数据缺失返回 `None`；格式损坏保留为错误。没有内容的孤立快照不能复用。
- 元数据始终发布完整快照；并发更新可以丢失部分结果，但不会读取正在写入的半份快照。
  不提供批量事务。

## 快速查询和索引恢复

- 统一 imohash-1.0 采样：至少 128 KiB 的文件在开头、中点和末尾各采样 16 KiB，
  较小文件完整采样。reader 接口使用固定句柄，不转换 UTF-8 路径、不按名字重新打开源文件。
- SQLite 只保存 `(imohash, blake3)` 关联，不保存业务元数据或持久文件身份。
  内容和对应的类型化快照仍是真相。
- `find_content` 采样输入，查询候选，再比较双方固定句柄的原生文件身份。
  共享身份走 `ContentVerification::FileIdentity`，避免完整哈希；imohash 自身不能证明相等。
- 独立副本、候选缺失/陈旧、索引不可用均回退完整 BLAKE3 校验，句柄报告 `Blake3`。
- 查询不导入、不改变权限、不发布快照、不更新或修复索引；SQLite 访问现有数据库时
  可能自行维护 WAL 运行时文件。
- 导入尽力登记候选，删除尽力清理。索引忙、损坏或版本不兼容不影响其他有效内容操作。
  只有显式 `rebuild_index` 执行派生数据恢复。
- 索引连接保留共享恢复 lease；重建必须先取得非阻塞独占 lease，才替换数据库/WAL/SHM，
  不会删除仍被协作连接使用的数据库。WAL 事务 busy timeout 为零，可选更新遇忙可以丢弃。
- 并发内容变化可使重建漏项或留下陈旧候选；候选仍需与当前内容访问核对，索引存在不代表可用。
- 身份快速路径依赖内容保持不可变。采样不能发现所有原地修改；所有者、管理员及已有可写句柄
  可以绕过保护。`check` 始终用于显式的完整性检查。
